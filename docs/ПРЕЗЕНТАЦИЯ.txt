МОГГНИТ · Smart Caspian Transit
Текст для защиты / презентации хакатона
========================================
Время: ~3–5 минут · можно читать почти дословно


1. ОТКРЫТИЕ (20–30 сек)
-----------------------
Команда МОГГНИТ представляет Smart Caspian Transit —
диспетчерскую систему для мультимодальных перевозок
на каспийском звене международного коридора «Север — Юг».

Груз идёт по цепочке: железная дорога → порт → море → порт → авто.
Одно опоздание — и вся стыковка разваливается: шторм, очередь в порту,
пропущенный рейс, дыра в документах. Логист обычно сверяет это часами
в разрозненных таблицах и переписке.

Мы собрали это в одно рабочее окно.


2. ПРОБЛЕМА (30 сек)
--------------------
На Каспии критичны три вещи:

• время стыковки с морским рейсом;
• погода и загрузка порта;
• комплектность документов до отправки.

Ошибка на любом из этих узлов даёт задержку, лишние деньги
и срыв контракта. Нужен не «ещё один дашборд», а система,
которая заранее говорит: «рейс не успеете» — и предлагает план Б.


3. РЕШЕНИЕ · ЧТО ПОКАЗЫВАЕМ (1,5–2 мин)
--------------------------------------
Открываем веб-диспетчерскую.

Обзор.
Сводка по коридору: активные перевозки, риски, задержки, документы.
Живая карта Каспия: суда, порты, штормовые ячейки. Диспетчер видит,
где сейчас напряжение на маршруте.

Перевозка SCT-2048 — наш главный кейс, Астрахань → Энзели.
В карточке — плечи маршрута, таймлайн, прогноз ETA и риск.
Сценарии «Шторм» и «Перегрузка порта» пересчитывают стыковку
и новый прогноз прибытия.

Альтернативы.
Текущий маршрут, через Махачкалу, через Актау.
Сравнение по времени, стоимости и CO₂e — логист выбирает план сам,
система не подменяет решение, а ускоряет его.

Документы.
Комплект из пяти файлов, проверка полноты, pre-check перед отправкой.
Понятно, чего не хватает и что исправить прямо сейчас.

Плюс сравнение грузов, аналитика коридора, уведомления в шапке
и ИИ-ассистент по данным системы — без «галлюцинаций» вне контекста.

Рядом работают Telegram-бот с теми же данными для дежурного
и мобильный клиент Flutter для работы вне рабочего места.


4. КАК УСТРОЕНО (30–40 сек)
--------------------------
Стек: React + TypeScript на фронте, FastAPI на бэке, SQLite локально.
Единый API обслуживает веб, Telegram и мобильное приложение.
Прогноз задержки — медианный baseline и CatBoost на истории плеч.
Карта — live-трекинг судов и прогноз штормов по Каспию.


5. ЦЕННОСТЬ (20–30 сек)
----------------------
Вместо часов ручной сверки логист за минуты видит:
сорванную стыковку, новый ETA, альтернативный маршрут
и статус документов — в одной диспетчерской.

Это экономия времени, меньше сорванных рейсов
и прозрачный контроль каспийского звена «Север — Юг».


6. ЗАКРЫТИЕ (15–20 сек)
-----------------------
Smart Caspian Transit — операционная диспетчерская МОГГНИТ
для коридора «Север — Юг»: риск, маршрут, документы и карта —
в одном контуре.

Спасибо. Готовы к вопросам.


СЦЕНАРИЙ КЛИКОВ НА ДЕМО (шпаргалка)
-----------------------------------
1. Обзор → KPI + карта → раскрыть карту → показать шторм/суда.
2. Уведомления в шапке → клик на событие.
3. Перевозки → SCT-2048 → сценарий «Шторм» → новый ETA.
4. «Сравнить альтернативы» → выбрать вариант.
5. Документы → показать дыру в пакете → исправить / добавить.
6. Ассистент: «Какие грузы под риском?» / «Что с SCT-2048?»
7. (опционально) Telegram-бот / мобилка.


ОТВЕТЫ НА ТИПИЧНЫЕ ВОПРОСЫ
--------------------------
Q: Это уже прод с реальными AIS/таможней?
A: Сейчас — полный рабочий контур диспетчерской на едином API.
   Интеграции РЖД, TOS, AIS и таможни — следующий этап;
   архитектура под них уже заложена.

Q: Откуда берётся прогноз?
A: Историческая медиана по плечам + CatBoost; сценарии шторма
   и перегрузки пересчитывают стыковку с расписанием.

Q: Почему не автовыбор «лучшего» маршрута?
A: Решение остаётся за логистом: система считает варианты,
   человек отвечает за коммерцию и договорённости.

Q: Документы = разрешение таможни?
A: Нет. Это контроль комплектности и pre-check пакета
   до отправки, не юридическое решение органа.
